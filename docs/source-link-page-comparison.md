# Source link page comparison

The theme suite compares the same owned comments in two complete documents:
the production Rust page and a page generated by the supplied original PHP
renderer. It checks link text, lexical destinations, deadlink text, quote
colors and decorations at desktop and mobile widths. It retains both full-page
screenshots for each of the six themes. The paired screenshots still need
review on the final head; a passing component assertion alone is not that review.

## Original capture

`fixtures/source-link-page.json` contains the original HTML and seven complete
stylesheets from revision `545b7812d1849f7958d914950c91fdbbe38f6b22`.
The capture uses `head`, `form`, `updatelog_real`, `renderPostHtml`, `foot` and
the original quote callbacks. The extractor checks whole-file and function
hashes before running those selected functions. It never starts the original
request handler or connects to a database.

The inputs are a closed `/g/` thread 100 and reply 123, anonymous names, fixed
timestamps, no images or pass badges, and a one-board navigation list. Lookup
stubs resolve post 123 to thread 100; other targets are absent. Page-title,
navigation and unused metadata helpers have explicit test values. The generated
HTML is captured in memory instead of written by the original page writer.
These stubs are not evidence for historical database visibility or access policy.

To verify the stored data, run:

```sh
python3 scripts/extract-source-link-page.py
```

To reproduce it with PHP and the pinned original checkout, run:

```sh
python3 scripts/extract-source-link-page.py --source /path/to/4chan-old
```

`--write` is an explicit capture update and still requires every source pin and
the reviewed HTML digest to match. Reference data must not be regenerated from
the replacement renderer to make a failing comparison pass.

## Browser isolation and substitutions

The original page runs with JavaScript disabled. Its four script elements are
removed, all external requests are blocked, and the captured stylesheets are
inlined. The test selects one original desktop theme and the source worksafe
mobile stylesheet, matching the fixture's board policy.

The supplied tree lacks `css/xa24extra.css`; that stylesheet is omitted rather
than replaced with guessed CSS. The background gradients, mobile button gradient
and closed-thread icon use the already-vendored image assets. Unused pass-badge
and red-button image URLs become empty data URLs. These substitutions are limited
to this fixture and are not claims that every historical asset was recovered.

Original cross-board destinations use `boards.example.test` in the isolated
oracle. The comparison removes only that exact controlled authority to compare
with the rewrite's same-origin route. Labels and fragments remain unchanged.
No production link is rewritten by the test.

## What the comparison establishes

The full documents expose quote styling in its page context, including the
mobile cascade, instead of checking a detached CSS rule alone. Assertions cover
live, leading-zero, signed and exponent links; absent and nonpositive targets;
unknown boards; ordinary external text; a source static link; and escaped entity
text. The existing persisted browser suite separately checks optional external
linkification, live insertion and viewer preferences.

Whole-page screenshots also reveal surrounding layout differences. The paired
review must record those differences rather than call these pages pixel-identical.
This link issue does not qualify every navigation control, posting form,
third-party stylesheet or the complete frontend rewrite. Those remain part of
the wider source/frontend parity work.
