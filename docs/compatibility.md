# Compatibility target

The pinned input is the public [4chan read-only API documentation](https://github.com/4chan/4chan-API/tree/2bd670d507ba2daa37a3961a661e088cf6f89d57), revision `2bd670d507ba2daa37a3961a661e088cf6f89d57`, collected September 8, 2026. [reference-manifest.json](reference-manifest.json) records exact source URLs and SHA-256 hashes. Files were fetched as public documentation; no live user posts, media or private source were imported. The input does not specify posting, authentication or private moderation behavior.

The official public [posting-options FAQ](https://www.4chan.org/faq#nonoko) is also pinned by collection time and response hash in the manifest. It supplies documented option meanings; no live external posting experiment was performed. See [posting-options verification](verification-posting-options.md).

No original visual reference snapshot or live posting observation has been collected. The separate `4chan-old` checkout has not been established as an approved source and was not used to implement this checkpoint. No independent design-brief attachment was available. Complete visual/behavioral parity remains unresolved. The current CSS is an original implementation of a compact, warm-colored board layout. Paperboard is not presented as an official service.

Evidence classes: **documented** means established by the pinned API docs or selected FAQ sections; **project** means a deliberate local behavior; **unknown** means reference evidence is missing. Status "implemented" applies only to the stated local scope, not universal client compatibility.

## Security-driven and project-defined exceptions

| ID | Reference/old behavior | Replacement and reason | User impact and test |
|---|---|---|---|
| E-001 | API documentation describes `.jpg`, `.png`, `.gif`, `.pdf`, `.swf`, `.webm` attachments | Production uploads and all original-download paths remain disabled; the explicit development profile publishes only normalized PNGs from the isolated PNG processor | No original download route or other format support. Private development input expires through queue cleanup. Startup/upload and intake tests. Worker containment does not make downloaded files safe in every client parser. |
| E-008 | Pinned media documentation uses `/{board}/{tim}s.jpg` for thumbnails and original-file metadata | The legacy-looking thumbnail route serves normalized PNG with truthful `image/png` and `nosniff`; full-file metadata and MD5 describe the normalized PNG | Retains one encoder and avoids another privileged image parser. Clients that require JPEG bytes at that route are not compatible. Actual byte, MIME, checksum, validator and deletion checks run in the browser test. Unknown legacy manifests omit missing fields until the isolated offline upgrade reproduces their exact approved PNG; original-upload checksum parity is not claimed. |
| E-007 | Original posting form sequencing is not established by the reference | Development image posting uses upload, POST status check, then the normal post form after approval | Keeps pending drafts/passwords out of worker waits and commits no unapproved attachment. Extra user interaction and a two-hour receipt deadline are project security policy. Real no-JavaScript browser test passes with synthetic validated pixels; full guest-backed browser qualification awaits CI. |
| E-002 | Raw HTML acceptance is not established by permitted posting documentation | User text becomes typed formatting nodes; Askama escapes every text/attribute | HTML appears as text. Unicode and real-browser hostile-text tests. |
| E-003 | Staff/password behavior is not specified by read-only API docs | Separate-origin staff WebAuthn with required user verification; operator-controlled invitations and recovery. Public author deletion still uses local Argon2 passwords | Staff requires a compatible authenticator and JavaScript. No password or recovery-code staff login. Virtual-authenticator and protected-schema tests; no hardware-attestation guarantee. |
| E-004 | Thread API documents `unique_ips` for active OPs | Omitted; persistent IP tracking is not implemented | Clients expecting that field need an exception. No invented count. |
| E-005 | `max_comment_chars` is described as characters without specifying the Unicode counting unit; media capacities as positive values | Comments count Unicode scalar values, with at most 16,000 characters and 64,000 UTF-8 bytes; media capacities remain zero alongside `text_only: 1` | `é` and `😀` each count as one scalar; combining marks, emoji modifiers and joiners count separately. CR/LF count individually when received. Text is not normalized. The original scalar/grapheme/UTF-16 distinction remains unknown. Real maximum-size form, storage, rendering, browser and migration tests; this is still a partial settings contract. |
| E-006 | Exact original posting cooldowns/deletion/concurrency rules are unknown | 30 writes per peer per minute, 32 admitted public/API handlers and retained response bodies/data, 4 Argon2 operations; active thread cap rejects overflow | Local overload remains 503 (staff has a separate 16-request budget and 429). No bypass through forwarded headers. Router, response-ownership and concurrency tests; production byte budgets and transport timeouts remain unqualified. |
| E-007 | Original retention behavior is unknown | Deleted text remains in PostgreSQL but disappears from public routes; reports persist | Compromised public database credentials can read retained content. Operator retention/erasure policy is a launch prerequisite. |
