# Per-job media execution

The implementation prompt authorizes completing the missing media boundary in issue #5. This design adds a local Linux qualification profile using Firecracker 1.16.1 and its matching jailer. The current Windows host provides an Ubuntu WSL Linux 5.15.153.1 environment with working KVM and cgroup v1 controllers. It is a disposable test host, not a qualified production processing tier.

The runner receives one operator-selected private input. It creates a fresh generated job directory, read-only input block device and fixed-size writable output block device. A pinned kernel and purpose-built initramfs boot the guest. No network interface, vsock, API socket, host directory share, database credential or host-management socket is supplied. The host does not mount or parse a guest filesystem. Guest output contains only the existing pixel protocol followed by zero padding. The host validates the entire bounded output after the VM has terminated.

Input is a big-endian u64 byte count followed by exactly that many bytes and zero padding to a 512-byte sector. The count is between 1 and 8 MiB. Output is exactly 4,194,816 bytes: `IBRGBA01`, big-endian u32 width and height, exactly width * height * 4 RGBA bytes, then all-zero padding. Dimensions are 1 through 1,024. Padding, dimensions, actual byte count, truncation and trailing bytes are checked independently of guest success. Invalid output is never promoted. The output device is preallocated and never mounted by the host.

The guest decoder runs without application credentials under an unprivileged identity. Its root init applies resource limits before dropping privileges. The VMM runs under a separate host identity inside the matching jailer, a private network namespace and externally limited systemd service. CPU, memory, file size, task count and wall time have explicit ceilings. A timeout or cancellation kills the full service. The runner reads output only after termination, then removes the per-job workspace and confirms no active service remains. A fresh guest is required for every attempt.

The runner's command interface is operator-only during qualification. It accepts no worker-selected command, executable, configuration path, output path or service name. Public applications cannot call a privileged shell or pass arbitrary systemd properties. Queue integration requires a separately authenticated fixed-protocol service and publication fencing before public enablement.

Tests use synthetic PNGs, pixels and harmless bounded probes. Connectivity checks require healthy owned positive controls. Resource checks exercise actual deployed limits and cleanup. Host/runtime/guest hashes and exact executed checks are recorded separately from unit tests. A successful local guest does not establish hardware mitigation, production host maintenance, independent review, original-file safety or complete format compatibility.

The upstream CI kernel is demonstration material; qualification must retain that limitation.
