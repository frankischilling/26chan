# Source image admission policy

Migration 0132 imports `MAX_KB`, `MIN_W`, `MIN_H`, `MAX_DIMENSION` and `GIF_ONLY` from the pinned board configuration. Global, category and board overrides follow the existing reference extractor. The default source limit is 4 MiB and its maximum dimension is 10,000. `/b/`, `/bant/` and `/s4s/` allow 2 MiB; `/wsg/` allows 6 MiB; `/hr/` requires at least 1000 by 1000 pixels. Only `/gif/` and `/wsg/` have `GIF_ONLY` enabled. The extractor preserves the applied 0045 and 0064 migration bytes.

Both public and staff attachment entry points apply policy after their existing board, thread and job locks. They use the capability's authenticated input length and the approval's dimensions and immutable output format. A filename cannot establish GIF identity. Rank, sticky and undead exemptions from reply-count limits do not bypass image format, size or dimension admission. Failed admission rolls back the post and leaves an unexpired unused receipt available for correction or cancellation.

The public and staff upload streams enforce the board's effective file limit before forwarding further chunks. Board JSON advertises that limit and includes minimum-width and minimum-height fields only when they exceed one, as the source does. Public file pickers offer GIFs on GIF-only boards, and the form shows the effective byte limit. The source size check charges input bytes, so a larger deterministic host encoding can still be admitted when its input fits. Client hints supplement the private database checks.

The transport's 8 MiB input bound and the decoder's 1024-pixel side bound remain independent security limits. The source `/f/` setting is 10 MiB, but its SWF workflow is unfinished and this change does not enable it. WebM, MP4 and PDF support remains unfinished. Source `GIF_ONLY` exempts WebM; the current approved formats are PNG and GIF, so that exemption still requires the separate video implementation. Source thumbnail dimensions, original PNG/JPEG retention and source GIF cleanup/MD5 comparisons remain separate work.

Apply the migration with writers stopped before starting binaries that read the new board fields. Existing posts, approvals and attachment bytes are preserved. The populated upgrade check compares all 82 source rows and preserves historical board fields, posts, threads and media metadata. Run `sudo bash scripts/test-image-board-policy-migration.sh` on an owned Linux host with PostgreSQL 16. It creates a private socket-only cluster and removes it on exit. Only the migration identity can change board image policy. The private helper has no runtime execution grant or schema creation permission; public and staff callers enter through their existing capability and posting-proof boundaries.

If text-thread transfer is already installed, the image migration checks its existing catalog guard before changing the board schema. Existing drift aborts the migration. The migration identity then records the reviewed schema change and rechecks transfer readiness. Runtime roles gain no catalog update or private hashing authority. If transfer is installed later, its migration captures the image-policy schema directly. The populated upgrade verifier exercises prior and later drift rejection whenever transfer is present.
